# Milestone C - Decision Support

## Purpose

Milestone C helps the user answer what to work on next.

The goal is to move selected backlog items toward realistic learning commitments without turning the product into a heavy planning system.

## Combined Focus

- Next-best-item guidance
- Time and commitment support

## What This Milestone Should Achieve

- Suggest the next best learning item or experiment.
- Surface realistic near-term candidates.
- Help convert selected items into actual commitments.
- Reduce hesitation when choosing what to study.
- Encourage small, realistic follow-through.

## Why It Matters

Milestone C is where Backlog Tamer starts changing behavior, not just organizing information.

The product should reduce overwhelm by narrowing the field of possible next actions and helping the user commit to something concrete.

## High-Level Success Criteria

- Recommendations feel realistic and useful.
- The product reduces overwhelm.
- More items move from backlog into action.
- Commitments feel manageable rather than aspirational.
- The user has a clearer sense of what to learn next.

## Product Questions To Resolve

- What makes an item a good near-term candidate?
- How should priority, effort, freshness, and user intent influence recommendations?
- Should commitments live in Notion only, Telegram only, or both?
- What is the lightest useful commitment format?

## Implementation Sense

This milestone should avoid over-planning. The recommendation layer should be lightweight, explainable, and grounded in existing backlog data.

The product should help the user choose and commit, but it should not yet try to schedule a full learning calendar.
