# Development Phases

Source: Notion page "Development Phases" under "Backlog Tamer".

## Roadmap Shape

Backlog Tamer should grow in this order:

1. Capture
2. Triage
3. Trust
4. Review
5. Planning
6. Specialization

Every phase should produce a usable improvement in real life. The roadmap should not add architecture for its own sake. Each milestone should make the learning backlog more intentional, easier to trust, or easier to act on.

## Milestones

### Milestone A - MVP

Build the smallest real product loop:

input -> interpretation -> confirmation -> structured Notion record

This milestone proves that Telegram capture, agent interpretation, user confirmation, and Notion persistence can work together as one reliable loop.

See [Milestone A - MVP](./milestone-a-mvp.md).

### Milestone B - Smart Triage

Improve the quality of decisions by using user intent, optional notes, and backlog hygiene signals. This milestone moves the product from simple storage into a stronger decision layer.

See [Milestone B - Smart Triage](./milestone-b-smart-triage.md).

### Milestone C - Decision Support

Help the user choose what to work on next and turn selected items into realistic commitments. This milestone starts changing learning behavior, not only organizing information.

See [Milestone C - Decision Support](./milestone-c-decision-support.md).

### Milestone D - Operating System

Create a sustainable weekly rhythm and introduce specialized product modules only after the core loop is trusted. This milestone turns the product into a repeatable learning operating system.

See [Milestone D - Operating System](./milestone-d-operating-system.md).

## Near-Term Recommendation

The first focus should stay on Milestone A, followed by Milestone B.

If those two milestones work well, Backlog Tamer will already be useful: it will capture learning inputs, interpret them, ask for confirmation, store them cleanly, and begin reducing backlog ambiguity.

## Product Guardrail

The roadmap should keep favoring clarity over surface area. Backlog Tamer should expand only when the previous milestone has made the system more useful, more trusted, or easier to act on.
